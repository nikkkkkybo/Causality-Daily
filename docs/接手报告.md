## 0. 先读这里（60 秒版）

- **这是什么**：一个独立的 Python + SQLite 命令行原型「因果簿」。它把内容拆成原子主张，记录每句话"我从谁那里读到、转述链的根是谁"，给出**未校准的实验分**，支持登记带截止日的明确预测，再由人对预测做 hit / miss / void 结算，最后生成手动日报。
- **当前状态**：核心账簿、出处链、评分、预测结算、日报、RSS/Atom 订阅→去重待读→本地一次采集推送、查询（`docs`/`doc`/`search`）、订阅条目转文档与**离线人工接账**（`ingest --claim`）、批量导入（`import-json --dir`/`--feed-item`）、跨源疑似重复提示、本地推送历史（`digests`）、紧凑简报（`daily --brief`）、本地单应用（`serve`）、**个体因果基线（`profile` + `daily --mode`，通线/轻个体线/个体线）、保险箱（DPAPI 加密 + 解锁审计）、7 天校准（`calibrate`）、盲评/消融（`eval`）、零月费云发布（`cloud` + GitHub Actions）与新版《今日事报》链式页（`daily_page`）**均已实现；离线测试 **321 个用例 + 119 个子测试全部通过**（2026-11-13 复跑）。首次真实公开源推送见 `push/2026-11-11/`（详细版 + 简报版，含人工接账与预测演示）。
- **当前阻塞**：真实 LLM 盲读抽取被 DashScope 免费额度限制（`AllocationQuota.FreeTierOnly`）卡住；当前 shell **没有设置任何模型密钥**。真实 RSS 抓取已通过一次性隔离验证（HTTP 200 / 24691 B / 50 条，见 §7.4）。
- **最重要的一条边界**：实验分不是真伪概率；预测命中不证明因果，预测失败也不证明来源失实；订阅条目只是"未核验的阅读候选"，不是主张。
- **不要做的事**：不要自动改计费/额度、不要自动外发数据、不要擅自安装系统定时任务、不要伪造"真实来源"、不要碰 `D:\ai奇门`（与本项目无关）、不要在 `D:\`（git 根）上做广泛 git 操作。

## 1. 项目背景与目标

### 1.1 用户原始诉求（摘要）

用户要解决的痛点是：互联网信息量极大、质量参差、时效难判，传统"读万卷书、行万里路"被社交媒体稀释；希望有一套机制，**默认接触到的内容是存疑的**，通过后续查询与长周期观察来修正判断，并产出每日推荐/日报。

用户提出的长期能力（按原意整理）：

1. 判断信息的准确性、出处（provеnance）与时效性。
2. 降低信息不对称，而不是重复消费同质化内容。
3. 导入自己关注的内容，支持查询/复盘。
4. 自动采集、推荐有用信息，生成每日报告。
5. 由"果"往回找到"因/源头"，也由"因"往前推可观察的后果。
6. 把庞杂的异构信息组织成关系网络。
7. 历史哲学/宗教/术数等体系只作为**假设结构与表示法**参考，绝不当作已证实的因果。

### 1.2 本项目边界

- 独立的"收集—解析—因果链"平台，**与 `D:\ai奇门`（奇门小镇）没有任何代码或运行依赖**，不读取、不整合、不修改它。
- 当前只实现"账簿"这一最薄纵切片：规则/先验生成预测，世界产生裁决，裁决回流账簿。**不实现**自动规则学习、因果识别、自动事实核查。
- 没有 Web UI、没有守护进程、没有系统定时任务、没有自动外发。

### 1.3 已批准的原型范围

导入内容 → 盲读抽取（LLM 只抽取不裁判）→ 出处链（isnad）→ 同主张合并 → 来源档案 → 确定性实验分 → 明确预测 → 人工结算 → 手动日报。

### 3.3 模型配置（可选功能）

`import --text/--file/--url` 需要外部模型；密钥优先级（`causal_ledger/extract.py:llm_config`）：

1. `CL_LLM_API_KEY`（可配 `CL_LLM_BASE_URL`、`CL_LLM_MODEL`）
2. `DASHSCOPE_API_KEY`（默认 base `https://dashscope.aliyuncs.com/compatible-mode/v1`，默认模型 `qwen-plus`）
3. `OPENAI_API_KEY`（可配 `OPENAI_BASE_URL`，默认模型 `gpt-4o-mini`）

安全与授权：

- 必须显式加 `--allow-remote`，否则在打开数据库之前就报错退出（不会建库、不会外发）。
- 内容会发送到配置的模型服务，可能产生费用。
- 模型返回的 `p` 会被删除；概率只能由人通过 `predict --p` 登记。

### 4.2 数据流

```text
                 ┌────────────── 订阅（RSS/Atom，不调用模型）──────────────┐
                 │  feed add ── feed import-file / collect ──> feed_items  │
                 │                                   （未核验、去重、未读）│
                 └───────────────────────┬───────────────────────────────┘
                                         │ inbox 人工挑选（主题/时间/每源上限）
                                         ▼
内容（手工 JSON / 文本 / 文件 / URL）──> 盲读抽取（LLM，仅抽取）──> documents
                                         │
                                         ▼
                              claims（canonical_key 合并）+ chains（reporter→origin）
                                         │
                                         ▼
                          确定性实验分（scoring.py，纯函数 + trace）
                                         │
                                         ▼
              predictions（明确文本 + 截止日 + 核验方法，可人工登记 p）
                                         │
                                         ▼
              settle（人工 hit/miss/void + 依据；Brier 只评该条预测）
                                         │
                                         ▼
              report / daily（手动或单次命令生成，不自动外发）
```

关键点：订阅条目**不会**自动变成 `documents/claims`；抽取必须由人发起（且要 `--allow-remote`）。评分与预测结算**不会**因为订阅/阅读行为改变。查询/桥接（2026-11-11 新增）：`docs`/`doc`/`search` 只读查看已导入内容；`ingest` 显式把 `feed_items` 转成 `documents`（默认只用摘要、不抽取；`--extract --allow-remote` 才抽取），`feed_ingests` 保证同一条目只转换一次。推送侧（2026-11-11 新增）：`recommend` 会在推荐依据里追加跨源"疑似重复（仅提示，未验证）"；`daily` 每次生成都会写入本地 `digests` 历史（不代表已投递或定时运行）。

## 5. 数据模型（SQLite）

### 5.1 表清单

| 表 | 用途 | 关键字段与约束 |
|---|---|---|
| `sources` | 来源档案 | `id`、`name UNIQUE NOT NULL`、`type NOT NULL`、`created_at` |
| `source_domain_stats` | 来源 × 领域 Beta 先验 | 主键 `(source_id, domain)`；`alpha/beta/n`；`source_id` 外键 |
| `documents` | 导入的文档 | `id`、`title`、`url`、`reporter_source_id NOT NULL→sources`、`raw`、`imported_at` |
| `claims` | 原子主张（合并后） | `canonical_key UNIQUE NOT NULL`、`text`、`domain`、`layer`、`hard_signal`、`credibility`、`trace`(JSON)、`created_at/updated_at` |
| `chains` | 出处链（isnad） | `claim_id→claims`、`document_id→documents`、`reporter_source_id→sources`、`origin_source_id→sources`、`quote` |
| `predictions` | 明确预测 | `claim_id→claims`、`text`、`due_date`、`check_hint`、`p REAL CHECK(p IS NULL OR 0<=p<=1)`、`status`(pending/hit/miss/void)、`brier`、`note`、`settled_at` |
| `credibility_log` | 实验分变动留痕 | `claim_id`、`old`、`new`、`reason`、`at` |
| `subscriptions` | RSS/Atom 订阅 | `url UNIQUE NOT NULL`、`enabled CHECK(0,1)`、`checked_at`、`last_error`、`created_at` |
| `feed_items` | 订阅条目（未核验） | `feed_id→subscriptions`、`item_key`、`title`、`url`、`summary`、`published_at`、`published_raw`、`fetched_at`、`read_at`、`UNIQUE(feed_id, item_key)` |
| `feed_ingests` | 订阅条目 → 文档桥接（幂等） | `feed_item_id UNIQUE NOT NULL→feed_items`、`document_id NOT NULL→documents`、`created_at` |
| `digests` | 本地推送/日报历史 | `created_at`、`kind`、`path`、`ok CHECK(0,1)`、`summary_json`（参数与采集结果） |
| `watchlists` | 关注主题（筛选标题/摘要） | `topic UNIQUE NOT NULL`、`enabled CHECK(0,1)`、`created_at` |
| `notes` | 本地应用"事报末尾备注" | `day NOT NULL`、`text NOT NULL`、`created_at`；只作下一次取舍的潜意识 |
| `profiles` | 个体因果基线（单行） | `id CHECK(id=1)`、`data_json`（仅公开/派生可用部分）、`mode`、`completeness`、`updated_at` |
| `vault` | 保险箱密文（单行） | `id CHECK(id=1)`、`cipher`（DPAPI 密文）、`fields_json`（仅字段名）、`created_at/updated_at` |
| `vault_audit` | 保险箱审计 | `action`（seal/unlock/clear）、`reason`、`created_at` |
| `calibrations` | 7 天校准历史 | `created_at`、`days`、`notes_count`、`deltas_json`（只存领域增量，不存备注原文） |
| `blind_votes` | 盲评投票 | `run_id`、`day`、`choice CHECK(A,B)`、`a_kind/b_kind`、`winner_kind` |

索引：`feed_items_unread ON feed_items(read_at, published_at, fetched_at)`；`feed_ingests.feed_item_id` 的唯一约束同时充当索引。

### 5.2 关键语义

- `canonical_key`：`主体|谓词|客体|时间范围` 的规范化字符串（去空白/转小写/全角竖线归一）；同一 key 跨文档合并成一条主张，不同来源不保证是独立证据。
- `chains`：每条主张可以有多个"读自谁（reporter）→ 引自谁（origin）"的链；`independent_origins()` 只按 `origin_source_id` 去重计数。
- `hard_signal`：**待核验线索**（如"PENDING: 交易所公告编号"），只保存，永不加分。
- `predictions.p`：人工登记的预测概率，登记后冻结；重复登记同一 `(claim, text, due_date, check_hint)` 且提供不同 `p` 会被拒绝。
- `feed_items`：`published_at` 是"源称发布时间"（无法解析或时区缺失则为 `NULL`，不编造），`fetched_at` 是首次采集时间；重复采集保留首次内容与 `read_at`。
- `feed_ingests`：显式记录"哪条订阅条目转换成了哪篇文档"；`feed_item_id` 唯一，保证重复 `ingest` 不会生成第二篇文档；它不改变 `read_at`，也不表示内容已核实。
- `digests`：每次 `daily` 生成后写一条本地历史（kind/path/ok/参数与逐源采集结果）；`ok=0` 表示部分源采集失败。它只记录生成行为，不代表已投递、也不代表定时任务在运行。
- `watchlists`：关注主题表；`inbox`/`daily`（含 `--brief`/`--html`）在未给 `--topic` 时默认使用启用主题筛选标题/摘要；主题只筛选，不评分、不核验。
- `notes`：本地应用里"事报末尾备注"的原文；提交后进入下一次取舍的潜意识（不是命令、不出现在事报正文）；空着不提交。

### 5.3 事务与原子性

- `db.atomic(conn)` 用 `SAVEPOINT ledger_write`，异常时 `ROLLBACK TO` + `RELEASE`，支持嵌套在外层事务中。
- `import_extraction` 整体原子：格式校验在任何写入之前完成；导入中途数据库错误会整体回滚（有触发器测试覆盖）。
- `store_feed` 先解析后写入，重复 key 用 `ON CONFLICT DO NOTHING`。
- 单连接、单机 SQLite；未启用 WAL；并发写入不在原型范围内。

### 5.4 迁移与兼容

`connect()` 每次都执行 `SCHEMA`（`CREATE TABLE IF NOT EXISTS`），因此**新增表**对旧库是加性的（`tests/test_subscriptions_schema.py` 验证旧 `documents` 表数据保留、重开后持久）。但：

- **没有列级迁移**。早期实验库如果字段与当前 schema 不一致（例如旧版 `predictions.p NOT NULL`），不会自动迁移。
- 结论：新功能请使用新数据库；不要依赖自动升级。

## 8. 认识论与产品边界（最重要的语义合同）

1. **实验分不是概率**：`credibility` 是确定性启发式排序分，未经校准；日报/CLI 均带免责声明。0.85 是启发式总封顶，不代表"85% 真实"。
2. **出处链不是独立验证**：`chains` 只记录"读自谁/引自谁"；相同 origin 名称去重、不同来源也可能共享同一上游。`independent_origins()` 只是计数，不是独立性证明。
3. **hard_signal 不是证据**：它只是待核验渠道提示（PENDING），不改变任何分数。
4. **预测概率只能人工登记**：`predict --p` 是人的判断；模型返回的 `p` 会被删除；登记后冻结。
5. **结算不回写**：hit/miss/void 只改该预测的状态、Brier 与人工依据备注；**不改变**来源 α/β，也**不改变**主张分数（`tests/test_ledger.py` 覆盖）。
6. **Brier 只评价那一条已登记概率的预测**：不能替代事实核查，也不能推出因果机制。
7. **日报是手动/单次生成的**：`daily` 不安装定时任务、不外发；采集失败会明确提示"不完整"。
8. **订阅条目不是主张**：`feed_items` 是未核验阅读候选；阅读/标记已读不改变账簿。
9. **不做因果识别**：预测命中 ≠ 因果证明；预测失败 ≠ 引用来源失实。

## 9. 安全与联网边界

- **URL 抓取**（`extract._fetch_public`）：只允许 HTTP(S)；拒绝凭据、非标准端口、控制字符、私网/保留/回环/链路本地/组播地址；DNS 全部答案校验后固定连接，保留 Host 与 TLS SNI/证书校验；每次重定向重新校验，最多 5 次；响应体上限 2 MiB；文档媒体类型白名单（HTML/纯文本/XHTML）；feed 额外接受 XML/RSS/Atom 与 `application/octet-stream`。
- **模型 API**：仅 HTTPS；禁止重定向（防 Bearer 泄漏）；校验 key 头字符；响应体上限；错误响应正文不回显（仅已知额度错误码映射为固定中文说明）。
- **RSS/Atom 解析**：拒绝 DTD/ENTITY（含 UTF-16/32 的 NUL 剔除后再检测）；最多 2 MiB、100 条；标题 500 字/摘要 4000 字截断；剥离 script/style/noscript/template、ANSI/终端控制序列、Unicode Cc/Cf/Cs；非法条目链接只丢弃该链接，不整源失败。
- **订阅登记**：`feed add` 只做语法/字面量校验（不 DNS），真实抓取时才解析并固定公网地址。
- **授权门**：任何把内容发送给外部模型的路径都必须显式 `--allow-remote`。
- **默认零外部源**：仓库不内置任何真实订阅源；`examples/` 内容全部虚构。

## 14. 术语表

| 术语 | 含义 |
|---|---|
| 因果簿 | 本项目名；账簿式记录信息、出处、预测与裁决。 |
| 主张（claim） | 单一主体 + 单一谓词 + 单一客体/数值/时间，可独立判真假的陈述。 |
| `canonical_key` | 主张合并键：`主体\|谓词\|客体\|时间范围`，规范化后相同即合并。 |
| 出处链 / isnad | 每条主张"读自谁（reporter）→ 引自谁（origin）"的记录；模仿圣训传述链的溯源结构。 |
| 独立根（origin） | 链的起点来源；不同名 origin 才能让 `independent_origins` 增加，但这不等于经验独立。 |
| 实验分（credibility） | 确定性启发式分数，用于排序；**不是**真伪概率，未经校准。 |
| 层级（layer） | intent（意图/传闻）、plan（已宣布计划）、formation（准备/进行中）、manifestation（已发生事实），各有分数封顶。 |
| hard_signal | 待核验的具体渠道线索（PENDING），只保存不加分。 |
| 预测（prediction） | 带明确文本、截止日、核验方法的可检验承诺；可选人工概率 `p`。 |
| 结算（settle） | 人工记录 hit/miss/void + 依据；只影响该预测，不回写来源/主张。 |
| Brier | `(p - 实际结果)^2`；只有登记了 `p` 的预测才计算。 |
| 实验性先验 | 来源类型 p0 与 α/β 伪计数（k=4），是工程假设，不是校准后的可靠率。 |
| 待读队列 | `feed_items` 中未读、启用订阅、时间窗口内的条目；未核验、非主张。 |
| 候选窗口 | `recommend` 只扫描最新 5000 条合格候选，空结果不代表全网无匹配。 |
