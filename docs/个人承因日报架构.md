# 个人承因日报：架构修正版

> 日期：2026-11-13　状态：架构定稿（替代"嵌入每条因果链"的旧说法）
> 核心修正：**承因的主体是"个人"，不是新闻事件。** 新闻、日期、历法、命理、结构、身心、行动，都是"因源"；日报输出的是"这些因如何落到你身上、今天怎么承、会结什么果"。
> 边界：只做个人承因与可验证建议；不输出命中注定，不把源系统当权威。

---

## 0. 先纠正我之前的错

我之前说"在每条因果链后加一条『落到你』"。这个说法仍然是**以新闻链为主、个人为辅**，不对。

正确结构是：

```text
个人（主体）
  ← 因源 A：今天几号、节气、昼夜、周期
  ← 因源 B：黄历/六曜/十二直/命理流日/占星行运/Panchang…
  ← 因源 C：世界信息（新闻/政策/价格）
  ← 因源 D：你的位置/结构/约束
  ← 因源 E：你的负荷/心身/关系
  ← 因源 F：你的行动
  → 承因：哪些因通过什么通道落到你
  → 果：今天要承的动作/风险/观察点
```

**新闻只是因源之一。** 没有新闻的日子，日期、历法、周期、你的位置，仍然可以产生个人承因。日报推送的不是"今天发生了什么"，而是"**今天你承了什么因、怎么承**"。

---

## 1. 因、承、果

| 概念 | 定义 | 不是 |
|---|---|---|
| **因** | 作用源：时间、信息、结构、身心、关系、行动 | 不是"新闻本身" |
| **承** | 这个因通过哪条通道落到你：领域、位置、约束、负荷、时窗 | 不是"事件归因" |
| **果** | 承因之后你今天的应对/状态/结果：做什么、不做什么、观察什么、怎么验证 | 不是"命中注定" |

一条承因卡 = **因源 → 通道 → 你 → 今日之果**。

---

## 2. 为什么还要每日推送

因为推送的不是"信息摘要"，而是：

> **每天一次的个人承因快照：今天哪些因在作用你、通过什么通道、你今天怎么接。**

- 有新闻时：新闻是因源之一，帮你看到世界因；
- 没新闻时：日期、历法、周期、位置、负荷仍然在作用，日报仍然有内容；
- 半黑盒：源系统的内部（卦象、神煞、星曜）不展开；你看到的是**个人承因与建议**；
- 溯源的作用：不是让你学算命，而是让我知道**每个因源该怎么接、接到哪一层、哪些分支可用**。

---

## 3. 因源分支：先建"家族"，再建"适配器"

### 3.1 因源家族

| 家族 | 分支举例 | 输出到承因的什么 |
|---|---|---|
| **时间/历法** | 日期、星期、节气、月相、季节、昼夜、个人日历 | 时窗、节奏、能量 |
| **传统时间系统** | 黄历宜忌、六曜、十二直、二十八宿、命理流日、紫微流日、六壬/小六壬、占星行运、Panchang/Muhurta | 领域激活、活动极性、时窗 |
| **世界信息** | 新闻、政策、价格、技术发布 | 世界因、结构因 |
| **位置/结构** | 角色、项目、行业、组织、杠杆、约束 | 承因通道 |
| **心身** | 负荷、睡眠、情绪、精力（可选） | 承受力、行动阈值 |
| **关系** | 家庭、同事、合作方 | 关系因 |
| **行动** | 决策、沟通、拖延、承诺 | 行动因 |

### 3.2 分支怎样建立

每个分支不是"信或不信"，而是一个 **adapter**：

```json
{
  "id": "huangli.yiji",
  "family": "traditional_time",
  "system": "huangli",
  "version": "A|B",
  "input": ["date"],
  "operation": "日期→建除/神煞/宜忌表",
  "normalize": {
    "domain": "career|wealth|health|relationship|family|learning|social|inner",
    "polarity": "favor|avoid|watch",
    "activity": "开新|收束|沟通|出行|财务|休息",
    "strength": "高|中|低",
    "window": "day|am|pm"
  },
  "hidden": true
}
```

**A/B 适配方式**：

- A 派、B 派、不同通书/流派，各自一个 adapter；
- 都归一化成同一张 `cause_signal`；
- 一致时取共识；冲突时降置信或输出"观察"，不强行合并；
- 用户不需要知道是哪一个派，审计里保留。

### 3.3 分支怎样选择

不是每天把所有分支跑一遍。选择规则：

1. **个人相关**：只保留与你的领域权重/目标/约束相交的分支；
2. **时间敏感**：当天/本周有窗口的优先；
3. **非冗余**：同一因、同一通道只留一条；
4. **可行动**：能变成"做/不做/观察"的优先；
5. **配额**：每天最多 2–4 条承因，避免信息过载；
6. **冲突处理**：两条因指向相反行动时，一条降为"观察"，另一条给条件；
7. **无强因时**：明确写"今日无强承因"，不硬造。

选择逻辑是半黑盒：你不必看分支表；你看到的是选后的承因卡。

## 4. 反理解：把源系统变成"承因适配器"

### 4.1 不是解释卦象，是提取操作语法

以黄历 + 命理为例：

```text
日期 → 黄历 adapter → 活动极性/时窗（宜收束、忌开新…）
日期 + 出生/档案 → 命理 adapter → 领域激活/周期主题（事业/财务/关系…）
你的档案 → 位置/约束/负荷
        ↓
候选承因：事业收束期 × 项目节点 × 负荷高
        ↓
承因卡：今天先收束、不做不可逆承诺；上午处理定义问题，下午沟通
```

- 不解释"为什么建除十二神这么排"；
- 不解释"某个星曜代表什么"；
- 只保留：**输入 → 极性/领域/时窗 → 个人承因**；
- 这就是半黑盒：符号层不展开，个人层可解释。

### 4.2 A/B 适配的处理

- 黄历 A 派说"宜开市"，B 派说"忌开市"：不选边，降为"观察/分歧"；
- 命理 A 派说"事业激活"，B 派说"财务激活"：取交集或分别给两张卡；
- 西方占星/Panchang 同理；
- **一致性不是真理，只是共识信号**；冲突本身是信息。

## 5. 每日事报的新结构

```text
《今日事报》
1. 今日承因（主体：你）
   - 因源：时间 / 传统时间系统 / 世界信息 / 结构 / 心身 / 关系 / 行动
   - 承因卡 1–3 张：因 → 通道 → 你 → 今日之果
2. 今日建议（从承因推出，不单独生成）
   - 做 / 不做 / 观察
   - 时窗、可逆性、验证方式
3. 世界信号（可选，作为因源之一的依据）
   - 因果链只在这里出现，不再"每条链加落到你"
4. 算法链与不确定性
```

### 5.1 承因卡格式

```text
【承因 1】时间因 · 高
今天几号/节气/周期：深秋、周五、你的项目节点前 3 天
黄历/命理透镜（隐藏）：收束期；事业主题被激活
通道：项目节点 → 本周决策 → 你的预算
今日之果：上午先收束/定义问题，下午再沟通；不做不可逆承诺
可能错：历法分支只作时窗提示，不是事件预测
```

### 5.2 示例（仅示意，不是实际历法结论）

- 因源：日期 + 你的档案（事业权重高、负荷高、项目节点临近）；
- 适配器：黄历分支给"收束/不宜开新"；命理分支给"事业主题激活"；
- 承因：事业 × 项目节点 × 负荷高；
- 今日之果：上午做定义/收束，下午做低风险沟通；暂缓不可逆承诺；
- 验证：今天是否避免了返工/冲突；一周后回看。

---

## 6. "果"是什么

- **不是事件结果**，是**个人承因后的应对结果**：
  - 你今天做什么/不做什么；
  - 你避开什么风险/抓住什么窗口；
  - 你事后能验证什么。
- 所以"承因有了果"= 每天的因源经过个人通道，产生一个**可执行、可验证的今日结果**，而不是"预测今天会发生什么"。

---

## 7. 我看到的是皮还是内容

- 我读到的不是只有百科皮：至少对黄历/通书/六曜/六壬/星历考原这条链有原典或馆藏参考；
- 但我不可能把每套术数的所有分支都逐一内化；也不需要；
- 做法是：**把可操作的分支编码成 adapter，把不能编码的标为"未知/不采用"**；半黑盒不是装神秘，是承认边界；
- 分支怎么建、怎么选、A/B 怎么合，是我要解决的工程问题；你不需要干预细节。

## 9. 实施顺序

1. 因源注册表 + 3 个 adapter（黄历、六曜、命理流日）；
2. `bearing.py`：七层通道映射 + 选择规则；
3. 日报新结构：今日承因 → 今日建议 → 世界信号（可选）；
4. 反馈闭环：做没做/有用/有害；
5. 扩 adapter（占星行运、Panchang、十二直等）；
6. 云端个体线：只同步非敏感派生特征，保险箱不出本地。

---

## 10. 边界

- 承因主体是个人，不是新闻；
- 新闻只是因源之一，不是日报中心；
- 源系统只做半黑盒适配器，不做权威；
- 不解释卦象/神煞细节，不要求用户学习；
- 不输出命中注定、恐吓、高风险指令；
- 不把"覆盖多"伪装成"准确"；准确靠个人反馈校准。

**地基表**：因源家族、状态（implemented/simplified/plugin/gap）、优先级与缺口，见 [承因地基](承因地基.md)。

## 11. 已实现原型（2026-11-13）

### 11.1 引擎与命令

- `causal_ledger/bearing.py`：
  - `temporal_signals`：星期/季节/月初月末 → 时间因；
  - `profile_signals`：领域权重/约束/负荷/目标 → 位置、结构、心理因；
  - `news_signals`：当日条目按领域映射 → 世界因；
  - `load_lens_file`：外部透镜 JSON → 归一化承因信号；
  - `build_bearing`：去重、配额、时间/个人/世界三层各取一张，最多 3 张；
  - `render_bearing_html`：独立承因页。
- `daily_page.py`：支持 `bearing_cards=`，可在《今日事报》里嵌入「今日承因」。
- CLI：

```powershell
python -m causal_ledger --db app\app.sqlite3 bearing --day 2026-11-13
python -m causal_ledger --db app\app.sqlite3 bearing --day 2026-11-13 --html .tmp\bearing.html
python -m causal_ledger --db app\app.sqlite3 bearing --day 2026-11-13 --json
```

### 11.2 外部透镜格式（黄历/命理/占星等）

半黑盒接入点是一个 JSON 文件；系统只吃归一化后的信号，不关心里面是六曜、建除还是星盘：

```json
{
  "signals": [
    {
      "source": "黄历·某派",
      "family": "lens",
      "domain": "career",
      "polarity": "favor",
      "strength": 0.6,
      "carrier": "今日时间窗",
      "path": "历法 → 项目节奏",
      "action": "把需要收束的事放在上午。",
      "uncertainty": "透镜只给时窗提示。"
    }
  ]
}
```

```powershell
python -m causal_ledger bearing --day 2026-11-13 --lens config\my-lens.json
```

### 11.3 当前边界

- 已真实接入：时间、档案、新闻；
- **简化传统透镜**：建除十二神（日干支 + 节气近似边界）+ 可选 `--birth` 日主关系；只给时窗/关系提示，不含神煞/宜忌全表，也不是完整命盘；
- 黄历/命理/占星：**只提供接入位与归一化协议**，不伪造具体宜忌/星盘结论；
- 需要真实数据时，由 adapter 生成上述 JSON，再交给承因引擎；
- 这样符号层保持半黑盒，个人承因层可解释、可替换、可审计。
