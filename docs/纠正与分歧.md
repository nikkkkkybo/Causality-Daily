## 1. 我不同意或需要纠正的说法

| # | 你的说法 | 我的判断 | 依据 | 状态 |
|---|---|---|---|---|
| 1 | "human3.0 那个开源项目" | **不准确**。HUMAN 3.0 是 Dan Koe 的流行框架/商业内容；GitHub 上的 `HUMAN3_PROMPT` 是**非官方社区修订提示词**，不是框架本身，也不是"开源项目"。 | [chiisen/HUMAN3_PROMPT](https://github.com/chiisen/HUMAN3_PROMPT) 自述"Unofficial community revision"；原始提示词在 Dan Koe 的 newsletter。 | 已纠正 |
| 2 | "手机端嵌框架 + API key，就能避免主机常开" | **不成立**（至少对"每天 7:30 微信推送"不成立）。手机后台定时在 iOS 基本不可靠；微信消息不能由手机 App 自己发给自己，必须经服务端/公众号/第三方推送服务。 | iOS 后台执行限制；微信推送通道的架构事实；前一版已讨论过 GitHub Actions/serverless 方案。 | 已纠正 |
| 3 | "个体因果寻源决定推荐的日报" | **过强**。个体因果影响的是**相关性、排序、可行动性**；它不能替代世界证据、事实重要性与规范判断。否则会变成"只推你已有立场的东西"。 | 因果推断与推荐排序的区别；回音室/自我实现风险。 | 已收敛为"影响排序，不决定真值" |
| 4 | "古籍/命理照搬即可，不用理解" | **有风险**。照搬结构可以用于实验，但若没有出处、失效模式与验证，就会复制巴纳姆效应、决定论和伪精确。 | [占星双盲研究](https://www.tandfonline.com/doi/abs/10.3200/GENP.135.3.287-300)；[Loevinger 模型批评](https://awspntest.apa.org/record/1977-08027-001)。 | 已改为"假设生成器 + 出处/失效模式" |
| 5 | "插件商城里有类似 Muse 的 harness" | **需要拆开说**。Muse 是 Meta 的个人 AI agent 产品；DSH 是 harness；商城没有官方" Muse 对等 bundle"，只有可拼装的零件（`dsh-mobile-harness`、`dsh-rss-daily`、`dsh-wechat`、`dsh-scheduler` 等）。 | 插件目录与 npm 元数据（见前一轮调研）。 | 已纠正 |
| 6 | "你能看到的因果链，必然叫算法链" | **部分成立**。任何形式化的因果表达都是模型/算法；但"是模型"不等于"因果不存在"或"可以任意编"。模型可以被检验、被反驳、被修正。 | 因果推断的基本立场；可见链是表示，不是本体。 | 保留为"认识论提醒" |
| 7 | 把 Server酱当成"微信官方推送"（若有此意） | **不是**。Server酱是第三方推送服务，通过它的服务号把消息送到微信；有配额、依赖第三方、存在账号/服务风险。官方路径是认证服务号模板消息或企业微信机器人。 | Server酱产品定位；微信开放平台规则。 | 已澄清 |
| 8 | 把 HUMAN 3.0 当成"测评/诊断" | **不是**。它是反思框架；其提示词明确说"不是验证过的评估"，禁止声称测准发展/诊断/看穿隐藏真相。 | HUMAN3_PROMPT 开头与边界声明。 | 已纠正 |

## 2. 我自己的错误（也要记）

1. **我照搬了 HUMAN 3.0** 做问卷，没先追溯它的来源，也没把命理/心理学接进去。→ 已出 [源流与整合](源流与整合.md)，问卷改 v2，四象限降为"三视角之一"。
2. **我一开始把"个体因果"做成了偏好/档案**，而不是"位置、时间、约束、杠杆"。→ 已在 [个体因果层设计](个体因果层设计.md) 与 [整合架构与双线](整合架构与双线.md) 中纠正。
3. **我提 Server酱时没先强调它是第三方**，容易让你误以为是微信官方。→ 本轮补上。
4. **我曾在没有基线时也想"显得懂你"**。→ 现在明确：没基线走通线，不假装个体化。

## 3. 尚未决、需要验证的判断

这些不是"你定"，而是我按默认先跑、用数据改。

## 4. 使用方式

- 每次出现分歧，追加一条；不删旧条，只改状态。
- 每月复盘一次：哪些纠正被验证、哪些我可能又错了。
- 如果我在某件事上为了顺从而没纠正你，你可以直接拿这份文档质问我。
-  mirror 规则：**同意要有理由，反对要有依据，不确定要标出来。**
