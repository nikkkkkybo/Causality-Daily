# 溯源总表与"反理解"嵌套

> 日期：2026-11-13　状态：一次性总表 + 体系设计
> 边界：**只做谱系与结构，不评价好坏、不判断准不准。** 文中的"确证/转述/托名/不明"只表示文献状态，不表示价值。
> 目标：把"趋吉避凶"各系统的生成语法反向拆开，嵌进《今日事报》，让**个人承因**更全面、更可校准。

---

## 0. 先定义两个词

### 0.1 寻源

问的是：**它从哪来、经过谁、何时、改了什么、哪一段失传或托名。**

不是问：它准不准、好不好、有没有效。

### 0.2 反理解

不是"相信它"，也不是"批判它"，而是：

> **把一套源系统的生成语法反过来拆开：它假设了什么、把什么映射到什么、在什么条件下才会给出某个输出；然后把它的"内核"映射到个人因果通道上，作为假设生成器，而不是结论。**

一句话：**顺向是"源→术→吉凶"，反向是"吉凶输出→术的假设→人的哪条因果通道"。**

## 2. 谱系收束：五条根、三次转形

### 2.1 五条根

1. **时间/天文**：观测、历法、周期、季节、昼夜；
2. **分类**：阴阳、五行、干支、方位、星宿；
3. **占卜程序**：龟卜、蓍筮、式盘、起卦、签诗；
4. **制度/文本**：王权、祭祀、历官、通书出版、行业；
5. **认知/社会**：不确定性、控制感、模式识别、协调、叙事。

### 2.2 三次转形

1. **时占 → 日占**：问一件事 → 给一天定调（六壬时课 → 六曜）。
2. **国运 → 个人**：天象/王权 → 本命盘/流日（两河 → 希腊化；星命 → 四柱/紫微）。
3. **仪式 → 日历/商品**：择日/占卜 → 通书/黄历/App/每日运势。

### 2.3 源头状态

- 有出土/原典：甲骨、式盘、日书、御定星历考原、六壬心镜、Enuma Anu Enlil 等；
- 只有后世转述/托名：紫微陈抟、六壬徐道符、六曜起源；
- 官方自承不明：《御定星历考原》"神煞之说则莫知所起……历代附益"；
- 日本馆藏参考也承认六曜"起源不明"。

**所以"源头"不是一条直线，而是一张图；图上有确证节点、转述节点、托名节点和不明节点。**

## 3. 反理解：把"源"变成"个人承因"

### 3.1 五步

```text
① 拆：源系统的本体/时间模型/操作/解释语法/隐藏假设
② 映：把隐藏假设映射到个人变量（领域/位置/约束/负荷/时间窗）
③ 筛：只保留能被个人数据检验的假设；剔除不可检验的形而上部分
④ 验：N-of-1、盲评、消融；记录"承因是否成立"
⑤ 嵌：把通过检验的承因写进《今日事报》，不显示源系统标签
```

### 3.2 七层承因模型

| 层 | 问什么 | 例子 |
|---|---|---|
| **世界因** | 发生了什么信号？ | 政策/价格/技术发布 |
| **时间因** | 什么周期/窗口？ | 季度节点、个人日历、精力节律 |
| **位置因** | 你站在哪？ | 角色、项目、杠杆、约束 |
| **结构因** | 什么制度/权力在起作用？ | 行业规则、供应链、组织 |
| **解释因** | 你用什么框架理解？ | 因果链、传统透镜、叙事 |
| **心理因** | 你现在的负荷/偏差？ | 注意力、情绪、确认偏差 |
| **行动因** | 你做了什么/没做什么？ | 决策、沟通、拖延 |

**个人承因 = 这七层里，哪些因通过什么通道落到你身上，以什么强度/时窗，你能做什么。**

### 3.3 承因卡 schema

```json
{
  "cause_id": "C-2026-11-13-01",
  "layer": "position",
  "carrier": "你的项目节点",
  "path": ["政策信号", "行业成本", "你的项目预算", "本周决策"],
  "strength": "高|中|低",
  "window": "2026-11-13 ~ 2026-11-20",
  "action": "先做可逆的小验证，不签不可逆合同",
  "uncertainty": "政策落地节奏未定",
  "evidence": ["I#12", "profile.goal", "note:2026-11-12"],
  "source_lens": "hidden: 择日/时间窗（审计可见，页面不显示）"
}
```

### 3.4 各源系统的"可反演内核"

| 源系统 | 不输出 | 反演成 |
|---|---|---|
| 六曜 | "今天大安/佛灭" | 日语气氛 + 社会协调时机（时间因） |
| 黄历宜忌 | "宜/忌某事" | 活动风险窗口 + 可逆性检查（行动因） |
| 四柱/紫微 | "今年事业变动" | 领域注意力分配 + 周期主题（位置/时间因） |
| 六壬/小六壬 | "卦象吉凶" | 一事一议的决策提问 + 等待信息（行动因） |
| Panchang/Muhurta | "吉时/凶时" | 个人精力/日程的时间窗（时间因） |
| 选举占星 | "择吉日" | 不可逆行动的时机条件（行动因） |
| 塔罗/签诗 | "牌义/签文" | 每日反思问题（心理因） |
| 决策日记/N-of-1 | "建议" | 承因是否成立的个人证据（验证层） |

## 4. 嵌套进《今日事报》

### 4.1 页面结构

```text
今日判断（thesis）
因果链（世界→结构）
  └ 每条链后加一行「落到你」：这条因通过什么通道到你的位置
今日承因（1–3 张卡）
  ├ 世界因/时间因/位置因/结构因/心理因/行动因
  ├ 强度、时窗、可逆性
  └ 一条小行动或"先观察"
算法链 + 不确定性
```

### 4.2 "落到你"的写法

- 不写："今天大安，适合签约。"
- 写："这条政策信号经行业成本传到你的项目预算；本周是可逆验证窗口，先别签不可逆合同。"
- 不写："你命盘事业宫被激活。"
- 写："你的档案里事业权重高、当前负荷高；这条信号落在你的项目节点上，值得多看一眼。"

### 4.3 隐藏透镜

- 页面不显示"这是六曜/黄历/紫微"；
- 隐藏审计记录 `source_lens`，用于消融与复盘；
- 这样既保留源系统的"生成语法"，又不把术数标签强加给用户。

## 5. "更全面、更准确"怎么定义

### 5.1 全面 = 覆盖层数

- 一条信号至少检查：世界、时间、位置、结构、心理、行动；
- 覆盖越多，漏掉的承因越少；
- 但"多"不等于"准"，只是候选集更完整。

### 5.2 准确 = 可校准

- 不是"命理命中率"，而是：
  - 承因是否真的落到你（事后核对）；
  - 行动是否有效/有害（N-of-1）；
  - 预测是否可反驳（预注册、结算）。
- 没有个人反馈，源系统再古老也不能提高你的准确率；只能提供假设。

### 5.3 评价指标

- 覆盖率：每条信号被几层承因解释；
- 校准度：承因强度 vs 事后结果；
- 行动价值：执行/有用/有害；
- 反事实：关闭某层后，判断是否变差（消融）。

## 6. 数据模型与模块

### 6.1 表/文件

| 名称 | 内容 |
|---|---|
| `provenance_nodes` | 系统/文本/器物节点；年代、地域、状态 |
| `provenance_edges` | 依赖/传播/转形；证据状态 |
| `lenses` | 每套源系统的生成语法（输入/操作/输出/假设） |
| `personal_causes` | 承因卡（七层、通道、强度、时窗） |
| `cause_feedback` | 执行/有用/有害/事后核对 |
| `daily_bearing` | 当日承因结果（隐藏审计） |

### 6.2 模块

| 模块 | 职责 |
|---|---|
| `provenance.py` | 只读谱系图；查询上游/下游 |
| `lens.py` | 源系统 → 候选假设（不含结论） |
| `bearing.py` | 个人变量 → 承因卡；七层映射 |
| `advice.py`（可并入 bearing） | 承因 → 小行动/观察 |
| `daily_page.py` | 渲染「今日承因」；隐藏透镜 |
| `calibrate.py` | 个人反馈 → 校准，不改基线 |

### 6.3 接口示意

```python
hypotheses = lens.generate(signal, systems=["liuyao", "huangli", "astro"])
causes = bearing.map_to_person(hypotheses, profile, day, signals)
cards = bearing.filter(causes, max_cards=3, reversible_only=True)
html = render_daily_page(items, day, synthesis=synthesis, bearing=cards)
```

## 7. 实施顺序（一次规划，不再一轮轮补）

1. **静态谱系表**：把本文件第 1 节落成 JSON/CSV；只读，不参与排序；
2. **lens 原型**：先做 3 个透镜（时间窗、领域激活、每日一问），输出候选假设；
3. **bearing 原型**：七层映射 + 承因卡；先本地个体线；
4. **页面嵌套**：链后加「落到你」，文末加「今日承因」；
5. **反馈闭环**：执行/有用/有害；两周复盘；
6. **消融**：关闭 lens/bearing，比较判断质量；
7. **云端**：只同步非敏感派生特征；保险箱不出本地。

---

## 8. 边界与失败模式

- 不把源系统当权威；只当假设生成器；
- 不输出"命中注定/大凶/保证"；
- 不碰医疗/投资/法律的高风险指令；
- 不把"承因"做成新宿命论；
- 不把"覆盖多"伪装成"准确"；
- 不让隐藏透镜变成不可审计的黑箱；
- 不用备注悄悄改写因果基线（意向层与强潜意识已分开）。

---

## 9. 一句话总结

> **寻源**是画一张"从甲骨/式盘/天象到六曜/黄历/命理/占星"的谱系图；  
> **反理解**是把这张图的生成语法反过来，落到"世界—时间—位置—结构—解释—心理—行动"七层承因上；  
> **嵌套**是让《今日事报》在因果链之后，写出"这条因如何落到你"，并用个人反馈校准，而不是用古老权威冒充准确。
