# 承因样板：各部分的产出链路

> 日期：2026-11-13　对应样板：[个人承因日报样板.html](../samples/个人承因日报样板.html)
> 目的：把"这页每一块是怎么来的"拆开，不讲玄的；本来就模糊的地方（建除/日主）保留模糊，不硬解释。

---

## 1. 总链路

```text
档案 JSON ──→ derive_features ──→ 领域/约束/负荷/目标
日期 ──────→ temporal_signals ─→ 时间因（星期/季节/月初月末）
日期+生日 ─→ traditional_signals → 建除 + 日主关系（简化）
新闻条目 ──→ classify_domains ─→ 信息因（领域命中）
外部透镜 JSON → load_lens_file ─→ 透镜信号（可选）
                    ↓
              build_bearing
        （去重 → 分组 → 评分 → 选 4–6 张）
                    ↓
            承因卡（因 → 通道 → 你 → 今日之果）
                    ↓
render_daily_page（承因区 + 因果链 + 算法链）
                    ↓
              HTML 样板
```

---

## 2. 逐段产出

### 2.1 顶部：样板说明

- 手写，不属于引擎；
- 作用：明确"真实信号 + 虚构档案，只演示结构"；
- 不放进生产日报：生产页只有通用免责声明。

### 2.2 今日承因（核心区）

每张卡由 `build_bearing` 产出，字段来源如下：

| 卡字段 | 从哪来 | 样板例子 |
|---|---|---|
| `family` | 因源类型 | time / position / world / lens |
| `carrier` | 具体承接点 | 收束日、事业权重 0.90、建除·定 |
| `path` | 从因到你的通道 | 长期权重 → 事业；日期 → 建除 |
| `action` | 今日能做的动作 | 给事业留明确时段；不做不可逆决定 |
| `uncertainty` | 这条最可能错在哪 | 权重不是当天状态；建除不含全表 |
| `strength` | 0–1 的启发式强度 | 0.45 / 0.90 / 1.00 |

选择逻辑：

1. 每个 `(family, domain)` 只留一条；
2. 按"风险/约束 → 时间窗 → 个人支撑 → 位置/主线 → 世界信息 → 传统透镜"取卡；
3. 风险/约束优先于"高权重领域"；
4. 最多 4 张；样板为了展示两种传统透镜，放到 6 张；
5. 没有强因就写"今日无强承因"，不硬造。

因源覆盖与缺口见 [承因地基](承因地基.md)；命令：`python -m causal_ledger bearing --coverage`。

### 2.3 时间因（time）

- 输入：日期；
- 函数：`temporal_signals`；
- 规则：
  - 周一：开局/排序；周五：收束/交接；周末：恢复；
  - 春展开、夏扩张、秋收束、冬蓄力；
  - 25 日后：结算；3 日前：定调；
- 不涉及个人命理，只是节奏提示。

### 2.4 档案因（position/structure/psych）

- 输入：档案派生特征；
- 函数：`profile_signals`；
- 规则：
  - 领域权重 ≥ 0.35 的前两个领域 → "给它留时段"；
  - 约束 → "先绕开硬约束"；
  - 负荷 ≥ 0.6 → "降低不可逆承诺"；负荷 ≤ 0.3 → "可推进难事"；
  - 目标 → "先问这件事是否服务主目标"。

### 2.5 信息因（world）

- 输入：当天条目；
- 函数：`news_signals` + `personalize.classify_domains`；
- 规则：
  - 标题/摘要命中你的高权重领域，才成为候选；
  - 输出是"先核对"，不是"已发生"；
  - 一条信息只取一个领域，避免一张卡塞太多。

### 2.6 传统透镜（lens）

- 输入：日期，可选生日；
- 函数：`traditional_signals`；
- 建除：
  - 日干支：儒略日精确计算；
  - 月建：按节气近似边界（可能差 ≤1 天）；
  - 建除十二神：`(日支 - 月支) % 12`；
  - 只给"时窗/活动倾向"，不含神煞、宜忌全表。
- 日主：
  - 用出生日干与当日日干的五行关系（同气/生我/我克/克我/泄）；
  - 只取日干一层，不含完整命盘、大运、流年；
  - 明确标"启发式，不是命运判断"。

### 2.7 因果链

- 样板：手写，为了展示"链一 / 链二"的结构；
- 生产：
  - 优先 DeepSeek 合成（严格 JSON，cause.id 必须来自输入）；
  - 失败/无 key → 确定性主题聚类；
- 链只回答"世界信号之间有没有可参照的关系"，不负责个人承因；
- 个人承因在上面的承因区，不塞回每条链。

### 2.8 算法链（页脚）

- 由渲染器自动生成：
  - 输入条数/来源数；
  - 入链/存目条数；
  - 是否 DeepSeek 合成；
  - 个体线/通线、是否读保险箱；
  - 未核验提示。

### 2.9 "这页是怎么产出的"（样板附加）

- 样板专用，手写；
- 生产页不显示，避免每页都像说明书；
- 调试/审阅时可用。

## 3. 样板里哪些是真实、哪些是示例

| 内容 | 真实性 |
|---|---|
| 14 条公开信号、标题、来源、时间、链接 | 真实（reports/data/2026-11-13.json） |
| 档案领域/约束/负荷 | **虚构**（演示用） |
| 生日 1990-01-01 | **示例**，不是你的 |
| 建除/日主 | 真实计算，但只取一层，**启发式** |
| 因果链 | **手写示意**，不是当天真实判断 |
| 承因卡选择 | 真实引擎输出（基于虚构档案） |

## 4. 怎么复现

```powershell
python samples\make_bearing_sample.py
```

脚本会：
1. 读 `reports/data/2026-11-13.json`；
2. 用虚构档案跑 `build_bearing`；
3. 用 `render_daily_page(personal=True)` 渲染；
4. 写入 `samples/个人承因日报样板.html`。

只跑承因、不看整页：

```powershell
python -m causal_ledger --db app\app.sqlite3 bearing --day 2026-11-13 --birth 1990-01-01
```

## 5. 当前刻意保留的模糊

- 建除只取一层，节气边界近似；
- 日主只取日干，不含命盘；
- 传统系统不解释"为什么这个神煞/星曜代表这个"，只给归一化后的时窗/倾向；
- 因果链的"强度"只是启发式，不是概率；
- "今日之果"是可执行/可验证的应对，不是事件预言。

这些地方不强行讲清楚，是因为它们本来就模糊；硬解释反而会变成伪精确。
