# 新旧对照：别再把"因果簿简报"和"今日事报"混在一起

> 日期：2026-11-13　状态：整理稿
> 这份文档只做一件事：把旧版和新版分清楚，说明现在哪些路径是新的、哪些是历史兼容、哪些还没迁移。
> 结论先行：**旧的是"因果簿简报"（卡片/KPI/待办/台账），新的是"今日事报"（链/因/果/我的链路/可能看错/算法链）。云端此前误用了旧渲染器，现已改为新格式。**

---

## 1. 两套东西分别是什么

### 旧：因果簿简报（legacy）
- 形态：统计卡、4 张等权卡片、"待你处理"、台账状态、接账/结算提示、未核验标签；
- 入口：`daily --brief`（文本）、`daily --html`（单文件卡片）、`daily --html-dir`（多页卡片站）；
- 代码：`report.render_brief`、`html_report.render_brief_html`、`html_site.render_brief_site`；
- 历史产物：`push/2026-11-11/今日简报.html`、`push/2026-11-11/site/`；
- 定位：**后台/归档兼容**，不再作为新推送的主形态。

### 新：今日事报（canonical）
- 形态：一句今日判断 → 2–3 条链（因 / 果 / 我的链路 / 可能看错）→ 今日算法链 → 页脚边界；
- 特征：阅读优先、无待办、无台账、无 KPI、无接账按钮；每条链带不确定性；
- 代码：`daily_page.render_daily_page`；
- 参考页：`push/2026-11-12/今日事报.html`（手写样张）；
- 个体线：`profile` + `daily --mode` + `calibrate` + `eval`；云端通线不读档案；
- 定位：**新推送的唯一主形态**。

## 3. 我具体搞混了什么

1. `cloud.build_report` 仍然 `import render_brief_html`，所以 GitHub Pages 上部署的是**旧卡片简报**，不是我们后来定义的《今日事报》；
2. 我随后写了 `daily_page.py`，但没有先做新旧对照，也没有把 `cloud` 切过去，等于又加了一套"新"，却没处理"旧"；
3. 文档里"今日简报/今日事报"混用，导致你看线上页面时觉得我们聊了很久的东西又丢了。

**修复**：`cloud` 已改为调用 `daily_page.render_daily_page`；新增 `test_daily_page.py`；云端重新跑一次后，页面标题、结构和链式内容都会是新版。

---

## 4. 当前判定规则

- 新功能只加在 `daily_page` / `profile` / `calibrate` / `eval` / `cloud` 上；
- 旧渲染器**只做兼容**：不删除、不加新功能、文档明确标注"legacy"；
- 新推送不再显示：待办、台账状态、接账按钮、KPI、结算提示；
- 个体线只在本机；云端只发通线，不读档案/保险箱；
- 任何"新页面"上线前，先跑 `test_daily_page.py` 与 `test_cloud.py`。

| `push/2026-11-11/site/` | 旧卡片站 | 保留为历史，不再更新 |
| 文档中的"今日简报" | 旧名 | 统一改为"今日事报"；历史产物名保留 |

---

## 6. 这次之后怎么避免再混

1. 先读这份对照，再动任何渲染/推送；
2. 改动前确认"这是新层还是旧层"；旧层只修 bug，不接新需求；
3. 每次部署后核对线上标题与结构（不是只看 200）；
4. 文档、测试、部署件三处同步，避免"代码新、页面旧"。
