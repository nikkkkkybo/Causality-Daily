# 个体因果层：把"给谁推"接进因果链（研究与设计稿）

> 状态：设计稿 / 研究笔记　日期：2026-11-12
> 目标：补上现有"因果推送"缺失的最重要一层——**个体因果**。不是做命理预测，而是借用命理系统的结构语法，描述"同一件事对不同人意味着什么、为什么是现在、他处在因果链的哪一段"。
> 边界：本文涉及命理/占星/术数，仅作**结构假设与注意力脚手架**，不当作事实或预测证据；不做医疗、投资、法律建议；个人数据默认本地、需明示同意。

---

## 0. 结论先说

现有系统做的是"世界 → 结构 → 链"：抓信息、找同构、推后果。它缺的是"世界 → **这个人** → 后果"。

- 同一条 AI 监管消息，对做模型的人、做投资的人、做内容的人、刚被裁员的人，因果位置完全不同；
- 推荐的价值不在于"这条重要"，而在于"**这条对你当前的位置重要**"；
- 因此需要一张**个体因果图**：领域（我在乎什么/我被什么约束）＋时间（我现在处在什么阶段）＋关系（这件事如何传导到我）＋杠杆（我能做什么）。

命理系统恰好是历史上最系统的"个体差异 + 时间 + 关系"建模尝试。我们要借的是它们的**语法**，不是它们的**结论**。

---

## 1. 命理系统里可借的结构语法

### 1.1 紫微斗数：领域本体 + 时间分片 + 变化类型

- **十二宫**：命宫、兄弟、夫妻、子女、财帛、疾厄、迁移、交友、官禄、田宅、福德、父母——一套现成的"人生领域本体"。
- **三方四正**：宫位之间不是孤立的，存在固定的关联结构；可类比为领域之间的"常连边"。
- **四化（禄、权、科、忌）**：不是事件，而是**变化的类型**——资源增益、权力/责任、名声/文书/学习、阻碍/执念/风险。适合映射"这条信息对该领域的力的方向"。
- **大限 / 流年 / 流月**：把人生切成阶段与年度触发器。工程上可当作"时间分桶与注意力窗口"，而不是命运预测。
  参考：[iztro 四化文档](https://github.com/sylarlong/iztro/blob/163606db393619a052863a6f1de593003b4d7b0c/docs/learn/mutagen.html)、紫微入门书对十二宫/大限/身宫的说明（[书讯](https://www.popularonline.com.my/default/catalog/product/view/id/142431/s/4712966623419/category/8/)）。

### 1.2 八字：关系类型 + 强弱 + 用神（杠杆点）

- **四柱**（年/月/日/时）给出"初始条件"的表示；**大运/流年/小运**给出时间轴。
- **十神**（比肩、劫财、食神、伤官、正财、偏财、正官、七杀、正印、偏印）是一套**关系类型学**：同辈/竞争、表达/产出、控制/规则、资源/成果、学习/庇护等。适合把"事件对人的作用"分类，而不是只按题材分类。
  参考：[八字命学（维基）](https://zh.wikipedia.org/w/index.php?title=%E5%85%AB%E5%AD%97%E5%91%BD%E5%AD%A6&oldid=53884029)。
- **旺衰、用神/忌神**：不是"好坏"，而是"当前结构里哪个位置是杠杆、哪个位置是约束"。可类比为个体的**可行动性/脆弱点**。
- **刑冲合害**：领域之间的冲突、合并、牵动；可作为边类型（冲突/绑定/牵动）。

### 1.3 梅花易数 / 六爻：体用与世应——"事件与我的关系"

- **体用**：体为自身/主体，用为所问之事/客体；以五行生克判断"用"对"体"是生、克、比和。工程上就是一个极简的**主体—事件关系判定器**：这件事对我是增益、消耗、还是同类？
- **动爻与变卦**：触发器与演化结果；对应"信号 → 变化 → 新状态"。
- **六爻的世应、用神**：世为自己，应为对方/环境；用神为所问主题。适合"具体问题"的因果定位。
  参考：[梅花易数（ctext）](https://ctext.org/wiki.pl?if=gb&chapter=475043)、[火珠林（维基文库）](https://zh.wikisource.org/w/index.php?title=%E7%81%AB%E7%8F%A0%E6%9E%97&oldid=2098392)。

### 1.4 奇门遁甲：时—位—角色配置

- **时家奇门**以时间起局，用**用神**代表所问之人/事，以九宫、门、星、神、干的关系判断格局。它提供的不是"命运"，而是**情境配置语言**：同一事件，在不同时间、位置、角色下，意义不同。
  参考：[时家奇门断卦核心思路](http://mp.weixin.qq.com/s?__biz=Mzk2NDg3ODE3OQ==&mid=2247484068&idx=1&sn=513c7cfd3a9f06a844540710780fdd39)。

### 1.5 占星：本命盘 + 行运

- **本命盘**是个体基线（宫位=领域，行星/相位=关系），**行运/推运**是时间层。与紫微/八字同构：基线 + 时间 + 领域 + 关系。
  参考：[《行运占星全书》](https://books.google.com.sg/books?id=9204DwAAQBAJ)。

### 1.6 共同的"个体因果语法"

把上述系统压成工程可用的六个原语：

| 原语 | 命理对应 | 工程含义 |
|---|---|---|
| **基线** | 命盘 / 四柱 / 本命盘 | 个体的稳定条件：角色、资源、约束、长期目标 |
| **领域** | 十二宫 / 宫位 | 生活领域与权重：事业、财务、健康、关系、家庭、学习、迁移…… |
| **时间** | 大运 / 流年 / 行运 | 阶段与时间窗：何时该注意，不是何时会发生 |
| **关系** | 生克 / 四化 / 刑冲合害 / 相位 | 事件对领域的作用类型与强度：增益、约束、冲突、绑定 |
| **主体—客体** | 体用 / 世应 / 用神 | 在这件事里"我是谁、事是什么、我处在哪一段" |
| **杠杆** | 用神 / 忌神 / 旺衰 | 我能动的地方与脆弱点：可行动性、代价、时机 |

## 2. 必须保留的怀疑

命理不是已被验证的因果科学。研究上至少要承认：

- **多派歧义**：同一命盘，不同流派/师傅读法不同；出生时间误差会显著改变结果。
- **巴纳姆效应**：模糊、普适的描述容易被当成"说中了自己"；双盲研究对占星与人格的匹配并不支持其有效性（如 [Science Versus the Stars 双盲实验](https://www.tandfonline.com/doi/abs/10.3200/GENP.135.3.287-300)）。
- **不可证伪的风险**：如果把一切结果都解释成"命该如此"，就失去检验价值。
- **统计与方法论问题**：命理统计需要预注册、对照组、盲评；否则只是事后叙事（参见[命理统计学方法论](https://shenghsuanlin.web.nycu.edu.tw/2020/02/27/632/)）。
- **隐私与伦理**：出生时间、地点、健康、家庭、财务属于敏感数据；不能擅自推断，不能用于歧视性推荐，不能外发。

因此本设计只把命理当**假设生成器**：它决定"我注意什么、怎么连、如何排序"，但每一条个体因果判断都必须能落到可观察、可反驳的个人后果上。

## 3. 个体因果层：工程结构

### 3.1 数据模型（草案，全部本地）

```text
profile(id, display_name, timezone, birth_time?, birth_place?, created_at, consent_flags)
  -- birth_* 可选；不填也能运行；填了仅用于"时间层"，不用于算命输出

domains(id, profile_id, key, weight, state, note)
  -- key: career/wealth/health/relationship/family/learning/social/home/travel/inner/parents/children
  -- weight: 0..1 当前重要性；state: 当前处境（自由文本）

goals(id, profile_id, domain, text, horizon, status)      -- 我想达成什么
constraints(id, profile_id, domain, text, severity)      -- 我不能/不敢/没时间做什么
events(id, profile_id, date, domain, text, kind)         -- 近期个人事件（自述）
journal(id, profile_id, date, item_id?, decision, outcome, note) -- 决策与结果
notes(id, day, text, created_at)                         -- 已有：事报末尾备注
```

### 3.2 个体因果图

节点：`self`、12 个领域、`goals`、`constraints`、`actions`。
边：从"世界事件"到领域、从领域到目标/约束、从约束到可行动作。

对每条候选信息生成 1–3 条**个体路径**：

```text
世界事件 E
  → 影响领域 D（sign: 增益/约束/冲突/绑定；强度 s）
  → 触及目标 G 或约束 C（相关度 r）
  → 可能后果 O（可观察；时间窗 T）
  → 可行动作 A（若有；不构成建议）
```

排序分（示意）：

```text
personal_relevance(E) =
  Σ_D  weight_D × impact(E,D) × confidence(E,D)
  × timeliness(E,T) × (1 + novelty(E)) × actionability(path)
```

- `weight_D` 来自 individual profile（我对哪些领域在乎/被约束）；
- `impact` 来自关系语法（生克/四化/体用/世应/相位等）；
- `confidence` 来自来源链与多源同向（复用现有出处链与 dedupe）；
- `timeliness` 来自个人时间层与真实截止日（不是命理预言）；
- `actionability` 来自 constraints/goals：若完全无法行动，降权，只作"存目"。

### 3.3 时间层：只做注意力，不做预言

可选两种输入：

1. **现实时间层（默认）**：个人日历、截止日、季节/周期（财年、考试、项目节点）、政策窗口；
2. **命理时间层（可选，半黑盒）**：大运/流年/行运只用于给"当前阶段"打标签（如"变动期/积累期/交付期"），**不输出具体事件预测**。

输出到推送时，只说"为什么是现在"（现实理由），不展示命理推演。

### 3.4 半黑盒映射（只在内存/隐藏审计中出现，不显示）

| 命理结构 | 个体因果层中的角色 |
|---|---|
| 十二宫 / 宫位 | 领域本体（career/wealth/health/...） |
| 大限 / 流年 / 行运 | 时间分桶与注意力窗口 |
| 十神 / 四化 / 生克 | 关系类型与作用方向（增益/约束/冲突/绑定） |
| 体用 / 世应 / 用神 | 主体—客体—主题的定位 |
| 用神/忌神/旺衰 | 杠杆点与脆弱点（actionability） |
| 多派歧义 | 不确定性权重；不合并成单一结论 |

这些映射进入**隐藏审计元数据**（参考 `今日事报.html` 的 `audit-v1` 注释）：记录每条推送用了哪些领域、哪类关系、哪条路径、强度与不确定度；不显示在页面上。

### 3.5 推送呈现（给个人看的部分）

每条链在现有"因 / 果 / 我的链路"之外，多两行：

- **为什么与你有关**：触及了哪个领域/目标/约束（用平实语言，不出现命理术语）；
- **你在哪一段**：你是旁观者、受影响者、还是可行动者；以及可观察的时间窗。

不出现"你会如何"，只出现"若……则可能……；你能做的是……"。

## 4. 如何验证个体因果（而不是验证命理）

1. **N-of-1**：把每条"个人后果/动作"登记为个人预测，到期用日记/备注结算；比较"个体化推送"与"非个体化推送"的盲评。
2. **盲评**：同一批信息，给两版：A 版本按个体因果排序，B 版本按通用重要性排序；你或独立评审判"哪版更值得看、更有解释力"。
3. **消融**：分别关闭"领域权重""时间层""关系语法"，看排序与你的选择是否显著变化；无贡献就降权。
4. **校准**：只统计"个人后果"的可观察命中率，不做"命理准确率"宣称；样本不足时只描述、不推断。
5. **反向检验**：故意保留一些"看似相关、实则无关"的条目，检查系统是否过度联想。

这部分与现有"先用后修"一致：先跑，按月复盘，不把任何结构当真理。

---

## 5. 最小可行版本（MVP）

先不碰出生数据，也不碰命理术语，只用**自述的个体基线**跑通：

1. 建 `profile`：时区 + 5–8 个领域权重 + 3–5 个目标/约束 + 近期事件；
2. 对每日候选信息做"领域 → 目标/约束"映射，生成个体路径与排序；
3. 每日事报新增两行："为什么与你有关""你在哪一段"；
4. 末尾备注继续作为偏好/状态输入；
5. 每月做一次盲评与消融，决定哪些结构保留。

之后再加可选的"时间层"（现实日历优先，命理时间层仅作内部标签），以及可选的出生数据（默认关闭、需明示同意）。

---

## 6. 需要你决定的事

1. **个体基线数据**：愿意提供哪些？（时区、当前领域权重、目标/约束、近期事件；出生时间/地点可选）
2. **主结构**：先用"领域图 + 关系语法"（紫微/八字骨架）还是先用"体用/世应"（梅花/六爻的简化版）？
3. **呈现**：个体因果是显式写在每条链里（"为什么与你有关"），还是只影响排序、不显示？
4. **隐私**：出生数据是否允许进入本地模型/本地文件？是否允许在调用外部模型时脱敏后使用？
5. **验证节奏**：每天记录、每月盲评；还是先用两周做小样本？
