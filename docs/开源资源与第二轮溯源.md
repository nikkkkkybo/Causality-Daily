这说明：**《协纪辨方书》不是"凭空创造"，而是把更早的《考原》《神枢经》《广圣历》《历例》等汇编、折算、制度化。** 这条"汇编链"可以继续往上追。

### 在殆知阁里找到的对应文本

- `易藏/术数/御定星历考原.txt` → 对应《考原》；
- `易藏/术数/六壬心镜.txt`、`六壬秘本.txt`、`六壬神课金口诀古本.txt`、`壬归.txt`、`壬学琐记.txt` → 六壬文本群；
- `易藏/术数/奇门旨归.txt`、`六壬兵占.txt` 等 → 相邻术数文本。

这些是 **A/B 级原文入口**，但还需核对：版本、刊刻年代、是否托名、是否删改。仓库只是"有这份 txt"，不等于"这是善本"。

## 3. 对六曜链的修正

第一轮写的：

```text
六曜 ← 六壬時課 ← 六壬 ← 式占/式盘 ← 阴阳五行/天文
```

第二轮能确认的是：

- **六曜算法可复现**：`qreki_py` 等能算旧暦→六曜；但代码只是现代实现，不解释来源；
- **六壬文本存在**：殆知阁有《六壬心镜》《六壬秘本》《壬归》等；可读原典；
- **"六曜直接来自六壬时课"仍是 C 级说法**：神社说明 + 现代算法，缺日本历法史论文的逐条核对；
- **"六壬 ← 汉代式盘"是 B 级**：式盘实物存在（A），但"六壬"这一命名体系何时成立，仍需书目/版本证据。

所以链路应标成：

```text
六曜（日本历注，C）
  ←? 六壬時課（功能/文本亲缘，C；是否直接演化待证）
    ← 六壬（文本群存在，B；命名年代待核）
      ← 式占/式盘（汉代实物，A/B）
        ← 阴阳五行/干支/天文（B）
```

**"?" 就是下一轮要验证的边，不能省略。**

## 4. 评估库能回答"准确率"吗？

`MingLi-Bench` 的题源是"全球算命师大赛"题目与标准答案，评测的是 **LLM 按命理体系答题的准确率**，不是"预测现实事件"的准确率。两者不能混：

- 答题准确率高 = 模型学会了该体系的规则与话术；
- 现实准确率 = 需要前瞻性、对照、预注册、结算，目前没有可靠数据。

所以它是一个**规则/推理基准**，不是"命理有效性"的证据。

## 5. 这轮结论

1. 开源库能帮我们做三件事：**复现规则、跨实现比对、顺着引文找原典**；
2. 它们不能替我们做：**版本学、历史优先权、现实准确率**；
3. `cnlunar` 的引文图是目前最有价值的入口：从《协纪辨方书》→《考原》《神枢经》《广圣历》→更早文本，可以逐层收束；
4. 六曜链的关键缺口在"六曜 ← 六壬时课"这一步，需要日本历法史/民俗学研究，而不是更多代码库。
