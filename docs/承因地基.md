## 3. 承因优先级阶梯

卡片顺序不是按分数随机，而是按"先保底、再时窗、再个人、再世界、再透镜"：

```text
1. 风险/约束   （硬约束、高负荷；priority ≥ 90）
2. 时间窗     （星期/季节/月初月末）
3. 个人支撑   （负荷余量、关系、备注意向）
4. 位置/主线  （领域权重、目标）
5. 世界信息   （当天条目）
6. 传统透镜   （建除/日主/外部插件）
```

规则：

- 每天最多 4 张（样板为了展示放到 6 张）；
- 同一 `(family, domain)` 只留一条；
- 风险/约束优先于"高权重领域"；
- 传统透镜只做时窗/关系提示，不压过个人约束；
- 没有强因就写"今日无强承因"，不硬造。

## 4. 信号归一化

所有因源最后都变成同一个结构：

```json
{
  "source": "个人约束",
  "family": "structure",
  "domain": "*",
  "polarity": "avoid",
  "strength": 0.55,
  "priority": 100,
  "carrier": "时间、现金流",
  "path": "约束 → 行动边界",
  "action": "先绕开硬约束；今天不硬碰。",
  "uncertainty": "约束是否仍有效，需要本人确认。",
  "evidence": ["profile.constraints"]
}
```

外部透镜（黄历/命理/占星）也走同一结构，所以可以替换、可以审计、可以消融。

## 5. 缺口与下一步（不假装已接）

1. **完整四柱/紫微**：需要出生时刻 + 节气/排盘数据；目前只有简化日主；
2. **六曜/十二直**：需要旧历数据；可做成外部 lens；
3. **六爻/小六壬**：需要起卦/时课数据；插件位已留；
4. **Panchang/Muhurta**：需要天文历法数据；
5. **占星行运**：需要星历；
6. **行动/承诺**：备注已接，但还没有"承诺是否兑现"的反馈闭环；
7. **反馈**：承因卡还没有"做没做/有用/有害"的记录表。

这些缺口在 `cause_sources.py` 里都是显式的 `plugin` 或 `gap`，不会伪装成已实现。
