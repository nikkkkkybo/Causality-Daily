# 周报与保留策略

> 日期：2026-11-13　状态：已实现（零月费云端）
> 结论：**日报只保留到周报产出；周报成为长期归档，并在页内保留"本周信号清单（保留出处）"，避免删日报后丢来源。**

---

## 1. 节奏

- **日报**：每天 07:30（Asia/Shanghai）生成 `reports/YYYY-MM-DD.html` + `reports/data/YYYY-MM-DD.json`；
- **周报**：每周一 07:30 汇总**上一个周一 ~ 周日**，生成 `reports/week-<周一日期>.html`；
- 周报生成成功后，删除上一周的日报 HTML 与 data JSON；
- **周一当天的新日报保留**（属于新一周），直到下周周报产出。

示例：
- 2026-11-16（周一）07:30：生成 `week-2026-11-09.html`（覆盖 11-09 ~ 11-15），删除 11-09 ~ 11-15 的日报；
- 11-16 当天的 `2026-11-16.html` 保留，11-23 周报产出后再归档。

## 2. 为什么周报要保留来源清单

删日报后，单条信号的标题/来源/链接不能一起消失，否则周报就成了"无法复核的结论"。因此周报页底部有：

> 本周信号清单（保留出处）：每条标题 + 来源 + 时间 + 原文链接。

周报仍然只给"链 + 来源 + 不确定"，不给待办/台账。

## 3. 失败与安全

- 周报渲染在删除之前完成；渲染失败/无数据则**不删除**任何日报；
- `cloud --weekly-only` 无数据时返回错误，保留日报，等下周再试；
- 周报页写完后才更新归档索引；
- 日报/周报都不读本地档案/保险箱；云端仍是通线。

## 4. 文件与命令

```text
reports/
  index.html                 # 周报 + 当前日报
  YYYY-MM-DD.html            # 当天日报（临时）
  data/YYYY-MM-DD.json       # 当天结构化信号（周报汇总用）
  week-YYYY-MM-DD.html       # 周报（长期保留，带来源清单）
```

```powershell
# 手动生成/重跑周报（默认上一个周日截止；可指定 --week-end）
python -m causal_ledger cloud --reports reports --weekly-only --no-push --week-end 2026-11-08
```

GitHub Actions 在周一（北京时间）自动执行 `--weekly-only`，然后统一提交 `reports/`。

## 5. 边界

- 周报仍是**确定性主题聚类**，没有模型二次合成时可能落到"本周没有形成清晰主题 / 存目"；
- 周报不替代本地账簿的核验、预测、结算；
- 公开仓库会保留周报与来源清单；个人档案/备注仍只在本地；
- 旧 `daily --html/--html-dir` 不参与周报，仍属 legacy。
