# 零月费云发布：GitHub Actions + GitHub Pages + Server酱

> 目标：每天 07:30（Asia/Shanghai）自动生成一份静态《今日事报》，发布到 GitHub Pages，并用 Server酱推一条微信通知；不租服务器、不让家里电脑常开。
> 边界：这是一条**云端通线**——不读取本地档案/保险箱，不做个体线，不接收备注；个体线与保险箱仍在本机。

## 前提与限制

- **Server酱是什么**：第三方微信推送服务（ServerChan）。你在 sct.ftqq.com 登录后拿一个 SendKey，程序向 `https://sctapi.ftqq.com/<SendKey>.send` POST 标题与正文，你的微信会通过"Server酱"服务号收到消息。它**不是微信官方接口**，免费额度/规则以其当前页面为准；key 等同于密码，只放 GitHub Secret。
- GitHub 账号；**公开仓库**的 GitHub Pages 免费（私有仓库 Pages 通常需要付费计划）。
- GitHub Actions 免费额度足够个人日报；定时任务可能延迟几分钟到几十分钟。
- 仓库连续 60 天无活动，GitHub 可能暂停定时工作流；手动 `Run workflow` 可恢复。
- Server酱是第三方服务，免费额度/规则以它当前页面为准；没有 key 时报告照常生成，只是不推送。
- `config/feeds.json`、报告与代码会公开（如果仓库公开）；**不要**把 `*.sqlite3`、档案、保险箱、备注提交进仓库。
- 这条路线不生成个体线，也不处理"末尾备注"；需要手机提交备注时，再加 Cloudflare Worker + KV 的备注接口。

## 目录

```text
.github/workflows/daily-push.yml   # 每天 23:30 UTC = 07:30 CST
config/feeds.json                  # 订阅源清单
causal_ledger/cloud.py             # 静态报告 + 归档 + Server酱
reports/                           # Actions 生成并提交归档（由 Pages artifact 发布）
```

## 一次性配置

1. **建仓库**：把本工程推到 GitHub（公开仓库）。
2. **开启 Pages**：仓库 Settings → Pages → Build and deployment → Source 选 **GitHub Actions**。
3. **加 Secret**（可选，但推荐）：Settings → Secrets and variables → Actions → New repository secret：
   - Name: `SERVERCHAN_KEY`
   - Value: 你的 Server酱 SendKey（在 sct.ftqq.com 获取）
4. **启用工作流**：Actions 页签 → `daily-push` → 允许；先点 **Run workflow** 手动跑一次。
5. **看结果**：
   - 报告归档：`https://<owner>.github.io/<repo>/`
   - 当日报告：`https://<owner>.github.io/<repo>/YYYY-MM-DD.html`
   - 若配了 Server酱，微信会收到一条带链接的消息。

## 本地先演练

```powershell
python -m causal_ledger cloud --config config/feeds.json --reports reports --no-fetch --no-push --date 2026-11-13
```

生成 `reports/2026-11-13.html` 与 `reports/index.html` 后，用浏览器打开检查版式。
真正联网演练（会请求订阅源，不推送）：去掉 `--no-fetch`，保留 `--no-push`。
推送演练（需环境变量 `SERVERCHAN_KEY`）：去掉 `--no-push`。

## 修改订阅源

编辑 `config/feeds.json`，每项 `{ "name": "...", "url": "https://..." }`；只接受 http(s)，最多 30 个，URL 不能重复。
改完手动跑一次 workflow 验证。

## 已知边界

- GitHub cron 用 UTC：`30 23 * * *` = 北京时间 07:30；GitHub 可能延迟。
- 报告日期按 **Asia/Shanghai** 计算，不按 runner 的 UTC 日期。
- 每次运行会把 `reports/` 提交回仓库归档，因此仓库会随日期增长；工作流需要 `contents: write`（已声明）。若仓库设置禁止 Actions 写内容，需在 Settings → Actions → General 把 Workflow permissions 改为 Read and write。
- 报告是**新版《今日事报》**（链式页：因/果/我的链路/可能看错/算法链），不是旧卡片简报；这是**通线**，不读档案、不做"与你有关/你在哪一段"。
- 旧 `daily --brief/--html/--html-dir` 仍输出旧卡片格式，属于 legacy；云端已切到新页。
- 无备注回传：手机只能读，不能提交；要备注再加 Cloudflare Worker/KV。
- 公开仓库意味着代码与报告公开；不要把任何个人数据放进仓库。
- Server酱 key 只放 GitHub Secret，绝不写进代码/日志。
